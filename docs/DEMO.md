# 8 分钟答辩与现场演示

> 目标：让评委在 8 分钟内看懂「是什么、凭什么、怎么做、边界在哪」。
> 现场演示控制在 2 分 20 秒～2 分 40 秒，留时间给提问。

---

## 0. 演示前 10 分钟检查

```bash
# 1. 启动前后端（会自动拉起 Python 量化服务）
npm run start:easy

# 2. 预热行情/宏观缓存，避免现场等待
#    打开「设置 → 数据缓存 → 刷新真实行情与宏观」
#    或执行：
curl -X POST http://127.0.0.1:8000/data/refresh

# 3. 运行一次配置分析，确认有最新结果
#    「配置分析 → 运行分析」

# 4. 运行一次智能决策，确认报告已生成
#    「智能决策 → 启动分析」
```

浏览器预开 5 个标签页：

1. `/console` 总览
2. `/console/portfolio` 持仓与目标
3. `/console/analysis` 配置分析
4. `/console/agent` 智能决策
5. `/console/reports` 研报与记录

备用：PDF 报告、3 张关键截图、1 段 2 分钟录屏。

## 1. 8 分钟结构

### 0:00–0:35｜开场：一句话说清

> “FinScope 是一个个人资产配置智能体。它把真实 ETF 行情、宏观、利率汇率，和你自己的持仓、负债、目标放进同一套约束，用风险平价、均值方差、Black-Litterman 给出**大类资产 + 策略 + ETF 落地**的配置建议，并生成可追溯的研报。它不推荐个股，也不承诺收益。”

### 0:35–1:20｜痛点：三个断点

1. **信息断点**：资讯很多，但不知道和我的钱有什么关系。
2. **配置断点**：知道要分散，但不知道具体比例，更不知道落到哪只 ETF。
3. **信任断点**：AI 给的建议像黑箱，数字无法核对。

### 1:20–2:20｜方案：一条可验证的决策链

- 数据层：真实 ETF 复权行情 + 宏观/利率/汇率 + RSS。
- 量化层：三套战略引擎 → 战术倾斜 → 约束投影 → 风险/回测/目标。
- Agent 层：8 个角色分工，LLM 只解释，审查员检查越界。
- 表达层：交互图表 + 表格 + HTML/PDF 研报 + 图像输入。

强调三个数字：**23 只 ETF、3 套战略引擎、6 套回测策略**。

### 2:20–4:40｜现场演示（按这个顺序点）

1. **总览**（20 秒）
   - 市场状态 40.4/100「中性震荡」；
   - 净资产 188.5 万、可投资 100 万、应急金 6.7 个月；
   - 最新建议：现金 +5%、中国债券 +8%、中国权益 -22%、黄金 +9%（约数，随数据更新）。

2. **持仓与目标**（20 秒）
   - 9 条持仓、2 条负债、3 个目标；
   - 指一下自住房产：计入总资产，但不进入可投资组合优化。

3. **配置分析**（50 秒）
   - 当前 vs 目标大类柱状图（中国权益约 57% → 35%，现金 10% → 15%）；
   - 三套策略对比（以页面实时结果为准）；
   - 目标 ETF 权重与再平衡清单（以页面实时结果为准）；
   - 点「风险」：VaR、压力测试、相关性；
   - 点「回测」：集成策略 vs 沪深300，强调月度再平衡与 10bp 成本。

4. **智能决策**（40 秒）
   - 输入任务：「请分析我的资产配置，给出未来 3 个月的再平衡步骤」；
   - 启动，展示 8 个角色的执行轨迹；
   - 指审查员：「未发现个股推荐、目标价或收益承诺」；
   - 打开 PDF 研报。

5. **市场与宏观**（20 秒）
   - 真实 ETF 报价、宏观观测日期；
   - 点「抓取真实资讯」，显示美联储/WSJ RSS 新增条数。

### 4:40–5:50｜技术实现：为什么不是套壳

- Next.js + Python 双服务：UI/用户数据 vs 量化/Agent。
- 风险平价：等风险贡献，SLSQP；现金上限 15%，防止低波动资产吞掉权重。
- MVO：期望收益向横截面均值收缩；协方差 Ledoit-Wolf 收缩。
- Black-Litterman：动量观点带置信度，避免直接拍收益。
- 约束投影：单只 ETF / 权益 / 海外 / 卫星 / 现金 / 换手。
- 回测：月度再平衡、只用历史数据、10bp 成本，避免未来函数。
- 风险：历史/参数 VaR、CVaR、4 个历史压力窗口 + 4 个假设冲击。
- Agent：工具只读量化结果；LLM 不改数字；审查员兜底。

### 5:50–6:40｜算法正确性与工程质量

- 140 条 TS 测试 + 6 条 Python 量化测试；
- 关键测试：风险平价权重和为 1、约束投影上限、BL 可行、VaR/CVaR 非负、回测无 NaN、目标月供；
- `npm run typecheck`、`npm run build` 通过；
- 失败降级：无网络用缓存、无 Key 用规则智能体、LLM 失败回退、数据不足显式标注。

### 6:40–7:20｜合规与边界

> “我们给的是资产大类、策略权重、ETF/基金筛选与再平衡步骤；不推荐个股，不给目标价、止损位或买卖点，不承诺收益。所有回测、VaR、压力测试都基于历史样本与假设。”

- 演示数据为虚构；
- 图像识别需用户核对；
- 报告与页面均有免责声明。

### 7:20–7:50｜价值与后续

- 对个人：把“看不懂的资讯”和“说不清的资产”变成一张可执行的配置表。
- 对行业：可解释、可审计的智能体范式，适合理财教育、投顾辅助、家庭资产梳理。
- 后续：因子归因、税务优化、实时行情、更多资产类别、多用户。

### 7:50–8:00｜收尾

> “看得懂市场，配得清资产。谢谢大家。”

## 2. 2 分钟极简版（如果时间被压缩）

1. 总览：市场状态 + 三个数字（净资产、可投资、应急金）。
2. 配置分析：当前 57% 权益 → 目标 30.5%；三套策略对比。
3. 风险：VaR 约 4%/月、压力测试最差约 -8%。
4. 智能决策：启动 → 轨迹 → 审查通过 → PDF。
5. 一句话边界：不推荐个股、不承诺收益。

## 3. 高频问答

### Q1：数据是真的吗？

A：ETF 行情来自 AkShare/东方财富前复权日线，宏观来自统计局/央行/FRED，页面标注最新交易日与观测日期。演示持仓是虚构的，避免隐私。没有用假数据冒充真行情；数据缺失会显式标注。

### Q2：LLM 会不会胡说？

A：三层。第一，LLM 只拿量化结果和工具输出，不接触原始计算；第二，组合经理只写叙事字段，不能改 allocation/trades/risk 数字；第三，审查员检查个股推荐、目标价、收益承诺、权重合计与风险提示。越界会移除并降低置信度。

### Q3：为什么不做个股推荐？

A：产品定位是个人资产配置，不是证券投顾。个股推荐涉及适当性、牌照与合规风险；我们选择把“大类比例 + 策略 + ETF 载体”讲清楚，把个股决策留给用户和持牌机构。

### Q4：风险平价/MVO/BL 凭什么可信？

A：不是“信某一个模型”，而是三套引擎互相校验：风险平价看风险贡献，MVO 看收益风险比，BL 把动量观点与市场均衡结合；最终还要经过约束投影。回测用月度再平衡和交易成本，避免未来函数。结果不是收益承诺。

### Q5：为什么现金目标 15%？

A：现金是政策缓冲，不是收益资产。风险平价会把低波动的货币 ETF 权重推得很高，所以我们把现金上限压到 15%，同时单独用应急金规划覆盖 3–6 个月支出。

### Q6：数据不够怎么办？

A：历史不足的 ETF 从优化池剔除并标注；宏观缺失不补数字；约束不可行时投影器回退到可行权重；回测数据不足直接返回失败原因。

### Q7：为什么用 Python + Next.js 两套服务？

A：量化生态（pandas/numpy/scipy）在 Python；UI 与用户 CRUD 在 Next.js 更顺。两边通过 JSON 契约解耦，量化服务可独立测试与替换。

### Q8：现场断网怎么办？

A：行情/宏观/报告都有本地缓存；无 LLM 自动切规则智能体；演示前已预热并准备 PDF/截图/录屏。

### Q9：创新点是什么？

A：不是“又一个聊天机器人”，而是把**信息、量化、约束、风险、目标、审计**串成闭环；LLM 只做解释，数字可追溯；建议落到 ETF 与再平衡清单；同时保留合规边界。

### Q10：商业模式？

A：课程阶段不考虑营收。可行方向：理财教育机构的教具、家庭资产梳理工具、投顾机构的辅助分析层。涉及投顾业务必须持牌并做适当性管理。

## 4. 现场故障预案

| 故障 | 处理 |
| --- | --- |
| 量化服务没起来 | 看终端日志；执行 `npm run quant:dev`；或直接用预生成的 PDF/截图 |
| 网络断了 | 用缓存；不点“刷新行情”；直接演示已有分析 |
| LLM 超时 | 取消“使用 LLM”，用规则智能体重跑（约 30 秒） |
| 页面白屏 | 刷新；检查 Next 终端；用备用标签页/录屏 |
| 时间不够 | 走 2 分钟极简版，重点讲配置对比 + 风险 + 边界 |
